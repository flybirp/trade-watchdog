# trade-watchdog

交易条件巡检搭档——读取 [trade-buddy](https://github.com/flybirp/trade-buddy) 产出的交易决策单，定期比对「达成条件清单」与「阻断条件清单」，**只在有事发生时才报告，无变化保持静默**。

![trade-buddy × trade-watchdog 协作关系与使用流程](overview.png)

## 它解决什么问题

trade-buddy 出的决策单里有两张表：

- **达成条件清单** —— 目标需要什么（例：指数 EPS 年增 ≥18%、PE ≥27 倍）
- **阻断条件清单** —— 目标不能有什么（例：连续两年 EPS 增速 <10%、ETF 溢价持续 >3%）

问题：这些条件写完那天就沉睡了。没人会每天翻出决策单逐条核对。

trade-watchdog 让它们活起来：**定期自动检查哪些条件命中、哪些逼近阈值、哪些人工项到了该查的日子**。

## 配合 trade-buddy 使用（核心流程）

```
┌─────────────┐      ┌──────────────┐      ┌─────────────────┐
│  trade-buddy │  →   │ trade-watchdog│  →   │  你（人工观测项） │
│  出决策单     │      │  定期巡检     │      │  按提醒去查      │
│  + 条件清单   │      │  比对阈值     │      │  年报/FOMC/研报  │
└─────────────┘      └──────────────┘      └─────────────────┘
       ↑                      │
       └────── 需重新评估时回到这里（watchdog 不做分析）
```

### 第一步：确认决策单可巡检

决策单必须包含：

1. **表 A · 达成条件清单** 和 **表 B · 阻断条件清单** 两节
2. 每条条件带 **「观测方式」** 列（这是 2026-09 版起新增的契约列）

「观测方式」三种写法：

| 写法 | 含义 | watchdog 的行为 |
|---|---|---|
| `westock: kline hkHSTECH --period day --limit 2` | 可自动取数 | 跑命令、比阈值 |
| `人工: 年报（每年 3 月，港交所披露易）` | 需人工查 | 不取数，时点到了提醒你 |
| `不可观测: 无公开数据源` | 查不了 | 跳过，只在人工复核时看 |

**老决策单缺列怎么办**：watchdog 会提示「该决策单版本较旧，缺『观测方式』列，无法自动巡检」，而不是硬扫（凭条件描述猜数据源，猜错比不查更糟）。解决办法：让 trade-buddy 按新版格式重新出单，或手动补上观测方式列。

### 第二步：触发巡检

直接说人话：

```
帮我盯一下 outputs/恒生科技指数(HSTECH)交易决策单-20260901.md
扫一下现在有哪些决策单的条件命中了
恒生科技这些条件现在什么状态
```

不指定文件时默认扫工作区 `outputs/` 下的所有决策单。

### 第三步：设置定时任务（可选，推荐）

**WorkBuddy** —— 直接说：

```
帮我建个定时任务：每个工作日早上 9 点，用 trade-watchdog 巡检 outputs 目录下
的所有交易决策单，只在有条件命中、状态变化或人工项到期时才报告
```

**Codex / 其他带 cron 的客户端** —— 按各自调度器的写法，prompt 保持同一句话即可。

### 巡检频率怎么选

**条件清单的性质决定巡检频率**，不是越勤越好：

| 决策单类型 | 建议频率 | 原因 |
|---|---|---|
| 短线交易单（几天~几周） | 每交易日 | 价格、成交额、资金流天天变 |
| 中线（3–12 个月） | 每周 | 混合了高频与低频条件 |
| 三年配置单 | **每月** + 年报季重点复核 | 核心变量（EPS、估值分位）季度/年度才更新 |

对三年期配置单做每日巡检，结果是大半个月每天都输出「无变化」——高频扫描低频变量只产生噪音，看两次你就免疫了，等于没有监控。

## 输出：什么情况会打扰你

**静默优先。** 只在四种情况报告：

| 情况 | 例子 |
|---|---|
| **条件命中** | 达成条件从「未达成」变「已达成」；阻断条件被触发 |
| **状态跃迁** | 任一条件的状态字段发生变化 |
| **逼近阈值** | 自动观测项进入阈值的 ±10% 缓冲带（预警） |
| **观测时点已到** | 人工项（年报/FOMC）到了该去查的日子 |

其余一律一行「无变化」。

巡检结果追加写入 `outputs/watch/<标的>.watch.md`（时间线，保留历史）。**原决策单绝不修改**——决策单是分析快照，watch 文件是状态时间线。

## 明确边界

| 不做 | 谁负责 |
|---|---|
| 重新评估标的值不值得买 | trade-buddy |
| 调整概率区间 | trade-buddy（第 7 步复盘） |
| 给新的买卖建议 | trade-buddy |
| 修改决策单的条件或阈值 | 你 / trade-buddy |

watchdog 的输出里出现「建议加仓」「建议止损」即为越界。

另一个关键区分：**数据缺失 ≠ 未达成**。命令跑失败或字段为空时标「数据缺失」（查不到），不是「未达成」（查到了但没到）。混淆会误导判断。


**方式二：git clone**

```bash

git clone https://github.com/flybirp/trade-watchdog.git ~/.workbuddy/skills/trade-watchdog
# CodeBuddy
git clone https://github.com/flybirp/trade-watchdog.git ~/.codebuddy/skills/trade-watchdog
# Codex CLI
git clone https://github.com/flybirp/trade-watchdog.git ~/.codex/skills/trade-watchdog
```

**前置依赖**：

- [trade-buddy](https://github.com/flybirp/trade-buddy) —— 本 skill 消费它产出的决策单，只装 watchdog 没有意义
- westock 数据通道（巡检自动项用）

**可选**：`futu:` 观测方式需要 trade-buddy 的 `scripts/futu_quote.py` + 本地 OpenD 运行。watchdog 会先 `probe`，OpenD 没开就整层跳过并标「数据缺失」——不会挂起任务，也不会中断巡检。

## 数据源与安全

自动取数只用两个通道（返回结构化数值，可做阈值比对）：

| 通道 | 命令 | 用途 |
|---|---|---|
| westock | `kline` / `asfund` / `hkfund` / `etf` / `technical` | 点位、量额、资金流、ETF 溢价、技术指标 |
| futu（OpenD） | `probe` 前置 | 卖空、每手股数、盘口、机构持仓 |

分析型数据源（`tencent-news`、`cninfo`、`agentic_search` 等）**不进自动巡检**——它们返回非结构化叙述，无法与阈值比对。依赖新闻/公告/研报的条件一律标 `人工:`。

内置 6 条「已知无效调用」防护（继承自 trade-buddy 的实测踩坑），包括最阴的一条：`asfund` 输出里内嵌 JSON 会导致按列 split 错位——**不报错，只会静默比错值**。watchdog 强制按表头行建 dict 解析。

本 skill 无脚本、无网络请求（除数据通道命令）、不写决策单、只读决策单 + 追加 watch 文件。

## 实测样例

恒生科技指数决策单（17 条条件，4 条可自动巡检）的一次真实巡检：

```
条件                    当前值      阈值         判定
表A-7 指数站上 5500     4565.85    ≥5500       未达成（差 16.7%）
表B-6 跌破历史低点      4565.85    <2720       未触发（高出 67.8%）
表B-5 ETF 溢价失控      +0.05%     >3% 且暂停  未触发
表B-7 ETF 成交额萎缩    15.4 亿/日  <5 亿       未触发

→ 无变化，静默。
```
